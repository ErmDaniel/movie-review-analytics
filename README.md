# Система рецензирования и анализа фильмов

Python-приложение для хранения, упорядочивания и анализа отзывов и оценок фильмов. Проект реализует предметные модели `Movie`, `User`, `Review`, сервисный слой бизнес-логики и CLI-интерфейс для работы с данными через PostgreSQL.

## О проекте

Основная цель проекта — построить модульную систему для работы с фильмами и отзывами, в которой:
- предметная область описана через отдельные модели;
- бизнес-логика сосредоточена в сервисном слое;
- слой хранения данных отделён от бизнес-логики;
- приложение можно использовать через CLI;
- данные можно хранить и загружать из PostgreSQL.

## 🛠 Технологии

- **Python** 3.13.5
- **PostgreSQL**
- [psycopg2](https://www.psycopg.org/)
- [python-dotenv](https://pypi.org/project/python-dotenv/) для загрузки конфигураций

## Основные возможности

## Итерация 1

Цель первой итерации — реализовать базовую модель данных и минимально работоспособную версию приложения.

- Реализация основных сущностей проекта: Movie, Review, User, а также логики взаимодействия между ними.
- Добавление, редактирование и удаление фильмов, пользовательских оценок и рецензий.

## Итерация 2

Цель второй итерации — расширить функциональность приложения и добавить работу с базой данных и аналитикой.

- Поиск и фильтрация фильмов:
  - по жанру;
  - по году выпуска;
  - по диапазону годов;
  - по подстроке в названии;
  - по средней оценке.
- Подключение PostgreSQL через библиотеку `psycopg2`.
- Отдельный слой хранения данных для фильмов, пользователей и отзывов.
- Загрузка данных в сервис из базы данных.
- Использование `.env` через `python-dotenv`.
- CLI-интерфейс для работы с приложением:
  - `cmd_find` — поиск фильмов по фильтрам;
  - `cmd_movie` — получение фильма по `id`.

## Архитектура

Проект разделён на несколько логических слоёв:

### 1. Доменный слой
Содержит модели предметной области:
- `Movie`
- `User`
- `Review`

Этот слой отвечает за структуру сущностей, инкапсуляцию данных и базовую валидацию.

### 2. Сервисный слой
Класс `MovieReviewService` инкапсулирует бизнес-логику:
- хранение коллекций фильмов, пользователей и отзывов;
- поиск объектов по `id`;
- пересчёт рейтингов фильмов;
- пересчёт числа активных отзывов пользователя;
- публикация, скрытие и удаление отзывов;
- поиск и фильтрация фильмов по заданным критериям.

### 3. Слой хранения данных
Слой хранения данных отвечает за взаимодействие с PostgreSQL:
- установление соединения с БД;
- выполнение SQL-запросов;
- загрузку данных из таблиц;
- преобразование строк БД в объекты моделей;
- сохранение данных обратно в базу.

### 4. CLI-интерфейс
CLI является пользовательским интерфейсом приложения и позволяет запускать команды из терминала:
- искать фильмы по фильтрам;
- получать подробную информацию о фильме по `id`.

## Настройка PostgreSQL

Для хранения данных используется PostgreSQL. Перед запуском приложения необходимо:
1. установить PostgreSQL;
2. создать базу данных;
3. создать таблицы `movies`, `users`, `reviews` (скрипт sql_scripts\create_tables.sql);
4. Заполнить таблицы (можно воспользоваться скриптом sql_scripts\fill_tables.sql)
5. настроить файл `.env`.

### Пример `.env`

```env
DATABASE_DBNAME=movie_reviews
DATABASE_LOCALHOST=localhost
DATABASE_PORT=5432
DATABASE_USER=postgres
DATABASE_PASSWORD=your_password
DATABASE_SCHEMA=public
```

### Описание переменных окружения

- `DATABASE_DBNAME` — имя базы данных.
- `DATABASE_LOCALHOST` — адрес сервера PostgreSQL.
- `DATABASE_PORT` — порт PostgreSQL.
- `DATABASE_USER` — пользователь базы данных.
- `DATABASE_PASSWORD` — пароль пользователя.
- `DATABASE_SCHEMA` — схема базы данных.

## Подключение к базе данных

Подключение к PostgreSQL выполняется в модуле `db.py` через `psycopg2`. Переменные окружения загружаются из файла `.env` с помощью `load_dotenv()`, а доступ к ним осуществляется через `os.getenv(...)`.

## Слой хранения данных

Для работы с PostgreSQL используется отдельный слой хранения данных. Он нужен для того, чтобы отделить SQL-логику от `MovieReviewService`.

В слое хранения реализуются репозитории:
- `MovieRepository`
- `UserRepository`
- `ReviewRepository`

Репозитории отвечают за:
- добавление сущностей в БД;
- получение сущности по `id`;
- получение всех сущностей;
- обновление данных;
- удаление данных;
- загрузку связанных сущностей.

Такое разделение позволяет:
- не смешивать SQL и бизнес-логику;
- легче тестировать сервисный слой;
- упростить развитие CLI и будущего API.

## Загрузка данных в сервис

Чтобы использовать уже существующий `MovieReviewService`, данные из PostgreSQL загружаются в сервис через отдельную функцию, например `load_service_from_db()`.

Общий порядок загрузки:
1. загрузить фильмы;
2. загрузить пользователей;
3. загрузить отзывы;
4. добавить их в `MovieReviewService`.

Этот порядок важен, потому что отзывы зависят от существования фильмов и пользователей.

## Поиск и фильтрация фильмов

Во второй итерации в сервисный слой добавляется метод `find_movies(...)`, который позволяет искать фильмы по нескольким критериям одновременно.

Поддерживаемые фильтры:
- `genre`
- `year_from`
- `year_to`
- `title_contains`
- `min_avg_rating`
- `max_avg_rating`

## CLI-интерфейс

Для работы с приложением реализован CLI-интерфейс на основе `argparse`.

CLI отвечает только за:
- разбор аргументов командной строки;
- загрузку сервиса;
- вызов методов сервисного слоя;
- вывод результатов в терминал.

### Поддерживаемые команды

#### 1. `find`
Команда для поиска фильмов по фильтрам.

Примеры:
```bash
python -m src.cli find --genre Sci-Fi
python -m src.cli find --year-from 2010 --year-to 2020
python -m src.cli find --min-rating 8
python -m src.cli find --title dark
python -m src.cli find --genre Drama --min-rating 8 --year-from 2000
```

#### 2. `movie`
Команда для получения информации о фильме по `id`.

Пример:
```bash
python -m src.cli movie 3
```

## Логика CLI-команд

### `cmd_find`
Команда:
- принимает значения фильтров из аргументов CLI;
- вызывает `service.find_movies(...)`;
- выводит найденные фильмы в читаемом виде.

### `cmd_movie`
Команда:
- принимает `movie_id`;
- вызывает `service.get_movie(movie_id)`;
- печатает подробную информацию о фильме;
- обрабатывает ситуацию, когда фильм не найден.
